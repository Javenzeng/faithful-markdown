# Operational lessons

## 2026-10-09 — GitHub 网络与系统代理

- 来源：Human 转述其他项目的实测经验；本项目尚未复测。
- 现象：浏览器可访问外网，Git push / Node fetch 仍超时。不能据浏览器正常就认定脚本网络正常。
- 下次 GitHub 推送超时时，先检查 Windows 系统代理配置及其端口是否监听。其他项目当时使用 `127.0.0.1:15556`；使用时读取当前配置，不固定该端口。
- 代理可用时，优先单次 `git -c http.proxy=http://127.0.0.1:<当前端口> push`；不擅自修改全局 Git 配置。
- Node 需按实际版本确认环境代理支持；其他项目以 `HTTPS_PROXY` + `NODE_USE_ENV_PROXY=1` 解决。仅相关任务需要时设置，并通过 `NO_PROXY` 排除 localhost / 127.0.0.1，避免影响本地服务。
- 复查触发：推送/抓取连接超时、代理端口或 Node 版本变化。代理端口未监听时，不强制走失效代理。
- 新版本治理收口时保留此条记录；本次未修改代理配置。
